DESIGNED TO KEEP WORK BOUNDED
  • 01

    Metrics with context

    Attempt duration, time to exposed headers, body-read time, start delay, timer lag, throughput and status distributions.

  • 02

    More than an average

    Min, mean, max, standard deviation and approximate P50/P95/P99 when enough samples exist. See errors, timeouts and cancellations separately.

  • 03

    Keep the data you need

    A dedicated worker streams and discards response bodies. Fixed histograms, capped samples and once-a-second UI updates keep reports bounded.

  • 04

    Stay in control

    Set concurrency, ramp-up, timeouts, variables and failure limits. Stop from the editor or dashboard. No automatic retries or catch-up floods.

Fetch-level timings include browser overhead. DNS/TLS, server-only timing and exact wire bytes are not available. CPU and memory use vary with the workload.

  1. 1

    Download & extract

    Download the extension ZIP and extract it to a folder. Use the release asset, not GitHub's source-code ZIP.

  2. 2

    Open Chrome's extensions page

    In Chrome's top-right menu ⋮, choose Extensions → Manage Extensions. Then enable Developer mode in the top-right corner. No address to copy.

  3. 3

    Load the extension

    Click Load unpacked. Choose the extracted folder containing manifest.json. Pin ApiSip from Chrome's extensions menu.

  4. 4

    Open your app & start capturing

    Review the first-install setup and click Allow website access. Open an HTTP(S) webpage, then choose Start capture. Response capture is enabled by default on new installs for available bodies and WebSocket messages. Use Alt + Shift + C to start or stop from a webpage; customize it in Chrome's extension shortcuts.

06 / THE USEFUL DETAILS

Before your
first sip.

Clear answers. Chrome's limits included.

Report an issue
Is ApiSip free? Do I need an account?+

All included features are free to use without an account or subscription. The source is public on GitHub. Supporting the creator is optional and never gates downloads or features.

Does this capture every browser request?+

No. ApiSip observes supported traffic after capture starts and site access is granted. Chrome-internal pages, other extensions, inaccessible targets and some worker/cache traffic are excluded or incomplete. Passive capture cannot read response bodies. Optional debugger capture adds bodies and timings where Chrome exposes them.

Why does Chrome show a debugging notice?+

Response capture uses Chrome's debugger API. Chrome displays a notice while it is attached. DevTools, another debugger or enterprise policies can interrupt attachment. You can turn response capture off and continue using passive request metadata.

How do the two replay contexts differ?+

Browser replay uses the original tab's cookie and CORS context and requires that tab to remain available at the expected origin. Extension replay uses granted host access and omits ambient page cookies. Both obey fetch restrictions; headers such as Cookie, Origin and Host cannot be reproduced freely. Errors and omitted headers are shown.

Can I send 10,000 requests in a minute?+

You can schedule 10,000 starts in a one-minute window. A local Chrome test completed that configuration with no missed starts, but it is not a guarantee for your API or computer. Concurrency, response time, rate limits and browser scheduling affect results. The runner reports missed slots, uses no automatic retries, and runs in extension context without ambient page cookies.

Where are my captures and credentials stored?+

In the extension's local IndexedDB storage. There is no cloud sync or telemetry. Display masking is not encryption: credentials can remain in local captures and editor drafts. Use the retention and deletion controls, and review exports before sharing. Timed-run reports omit request bodies, credentials and variable values.

Chrome says the manifest is missing. What now?+

Extract the release ZIP first, then choose the folder that contains manifest.json. Do not select the ZIP, a parent folder, src or public. If you cloned the source repository instead, run npm ci and npm run build, then load its dist folder or repository root. The README has the full build guide.

How do I update without losing local history?+

Keep the same unpacked installation folder. Close or stop active timed runs, replace the built files with the new release, and click Reload on ApiSip's card at chrome://extensions. Reload open inspector/editor tabs too. Moving the folder gives Chrome a separate extension identity. Export important history before updating; drafts and timed reports have separate storage/export behavior.

Does it work on every browser and operating system?+

ApiSip targets desktop Chrome 125+ using bundled browser APIs, with no OS-specific companion program. Automated extension testing currently covers Chrome for Testing on Windows. Other operating systems and Chromium browsers have not been fully verified. Firefox, Safari and mobile Chrome are not supported builds.
